# Outfish → PHH / 220.lv — Единые правила проекта

**Статус:** обязательные пользовательские правила и контрольный список для всех последующих действий по проекту.  
**Обновлено:** 2026-10-06.  
**Приоритет:** прямые новые указания пользователя могут изменить правила; фиксировать изменение здесь в том же рабочем цикле. Перед выбором товара, подготовкой, импортом, изменением, сверкой и публикацией читать этот документ полностью.

## 1. Границы проекта и источники данных

- Работаем с каталогом Outfish (Shopify), каталогом/предложениями PHH/220.lv и согласованным Master. Предпочтительна подготовка через staging.
- Shopify — источник фактических остатков по **конкретному варианту/SKU**. Не выводить общий остаток модели из остатка одного размера.
- Master и Shopify не изменять без отдельного явного разрешения. Факт чтения источника не даёт права на запись.
- PHH цены и остатки также не менять без отдельного разрешения на конкретную операцию или утверждённый режим синхронизации. Подготовка/расчёт **не равны публикации**.
- Авторизация и секреты PHH должны оставаться на стороне защищённого сервиса. Не выводить токены/пароли в логи, ответы и GitHub.

## 2. Запреты на публикацию и выбор товара

1. **ВЕСЬ бренд FHM полностью исключён из импорта в PHH/220.lv.** Никаких новых карточек FHM, независимо от их наличия в 220.lv.
2. **Уже существующие в 220.lv товары не создавать заново.** До CREATE сверить EAN-13 и UPC-12, SKU/вариант, действующие предложения продавца и доступную историю импорта. У разных вариантов (цвет/размер) проверка проводится отдельно.
3. Если API вернул 404 на *конкретный* маршрут, это ещё не доказательство отсутствия товара; если 429/503/таймаут/неполные результаты — статус **BLOCKED / UNKNOWN**, не CREATE.
4. Дубликат найден → **SKIP_EXISTING**. Товар не найден при исчерпывающей проверке → возможна дальнейшая подготовка/одобрение. Сопоставление не удалось → **REVIEW/BLOCKED**, не подбирать другой SKU наугад.
5. Не делать новую запись «для теста», если её можно безопасно проверить на существующей карточке. Отдельное разрешение требуется на реальный CREATE/PATCH.

## 3. Обязательное правило остатков Shopify → PHH / 220.lv

Применять **для каждого SKU/размера/варианта отдельно**, только в разрешённой синхронизации.

```python
phh_stock = 0 if shopify_stock == 0 else max(3, shopify_stock)
```

| Shopify (шт.) | Целевое PHH (шт.) |
|---:|---:|
| 0 | 0 |
| 1 | 3 |
| 2 | 3 |
| 3 | 3 |
| 4 | 4 |
| 5 | 5 |
| 10 | 10 |

- **Никакого положительного PHH-остатка меньше 3.**
- При следующей сверке: если фактический Shopify остаток стал **0**, обязательно передать **0** в PHH. Нельзя удерживать 3 по инерции.
- Реальный Shopify остаток не увеличивать ради PHH, это лишь правило отображаемого/передаваемого PHH количества.
- Не путать запланированный остаток и фактически опубликованный. При отсутствии права на запись только рассчитывать dry-run.

## 4. Варианты, размеры и идентификаторы

- Обувь: один товар-модель/цвет со своими размерами; у **каждого размера свой вариант/SKU**, EAN (если есть), свой реальный остаток Shopify, свой целевой остаток PHH.
- Не говорить «всего 4 пары», если 4 относится только к EU 40. Сначала перечислить и проверить все варианты модели.
- SKU может быть нестандартным/составным: сохранять исходные данные, неоднозначные варианты отправлять в REVIEW; нельзя молча брать кусок составного SKU.
- EAN проверять контрольной цифрой, не угадывать. Не подставлять UPC/EAN из похожей вариации без источника и проверки.

## 5. Подготовка карточки

- Заголовки и описания готовить на **LT, LV, EE, RU, FI**; не смешивать переводы и не использовать вымышленные технические характеристики.
- Категория PHH — подтверждённый ID из актуальной таксономии. Для каждой категории прочитать обязательные атрибуты и их **точные каталожные названия** (обычно LT в Product Import API), а также проверить допустимые значения селектов.
- Все обязательные характеристики должны пройти проверку. Если значение не определено, **REVIEW/BLOCKED**, а не молча пропускать.
- Изображения — реальные изображения конкретного Shopify товара, валидные прямые публичные URL без query string при PHH-импорте; не из похожего товара. Количество/порядок проверять.
- Производитель, модель, цвет, материал, размеры, комплектность и упаковка — только из подтверждённых источников. Физический размер товара **не равен** размеру транспортной упаковки.
- Для созданного товара с недостающими атрибутами исправлять **существующую карточку** после проверки идентичности; не создавать дубликат.

## 6. Обновление существующего товара и API-безопасность

- Перед записью: seller ID, полный identity preflight, SKU + EAN/UPC, история операций, актуальная категория и список изменений.
- PATCH разрешён только если подтверждён существующий товар; не отправлять POST CREATE взамен PATCH.
- Не считать HTTP 200 или import «success» доказательством полного заполнения: проверить результаты импорта, сообщения о непринятых/неизвестных характеристиках и, где доступно, карточку в PHH.
- 429/503 и другие ошибки доступа **не обходить массовыми повторами**. Сохранённый токен/пауза авторизации не гарантируют, что блок снят через ровно час.
- One-shot флаги записи включать только для явно одобренной операции и выключать после попытки. Перед следующей попыткой проверять предыдущие операции для предотвращения двойной записи.
- Все изменения должны быть минимальны по области. Не менять цены, остатки, упаковку, другие карточки или источники, если не разрешено отдельно.

## 7. Известные кейсы и актуальные предостережения

- **GearAid 68150**: SKU `68150`, EAN13 `0021563681505`, UPC12 `021563681505`, PHH категория `3377`. Товар был создан по успешному импорту `58291763`; в результате пять атрибутов были проигнорированы из-за неверных имён полей. Исправление существующей карточки остаётся отдельной задачей; при последней попытке PHH вернул 429 и сообщил `writes: 0`. **Нельзя создавать повторно.**
- **GearAid 68154**: подготовлен кандидат, но не считать отсутствующим в PHH без проверки.
- **GearAid 16110-010**: магазин Shopify содержит товар, PHH наличие не подтверждено; не CREATE без сверки.
- **LOWA RENEGADE II GTX MID TF MF Black, EU 40**: Shopify SKU `310921 999940`, размер EU 40 — 4 пары (это **не** общий остаток модели). В модели 10 вариантов; перед PHH сверять весь список и идентичность каждого.
- Для всех FHM: **EXCLUDED**, без исключений.

## 8. Контрольный список перед каждой операцией

1. Прочитать этот файл; определить тип операции (READ / PREPARE / CREATE / PATCH / STOCK_SYNC).
2. Убедиться, что бренд не FHM.
3. Прочитать актуальные SKU/варианты, EAN и остатки в Shopify; не полагаться на старые данные.
4. Для CREATE сверить текущую PHH идентичность (EAN13/UPC12, SKU, предложения, история). При проблеме доступа — STOP.
5. Проверить PHH категорию, обязательные поля, допустимые значения, 5 языков, фото и достоверную упаковку.
6. Применить правило остатков *только* к dry-run или к отдельно одобренной синхронизации.
7. Подтвердить права на конкретную запись. Без явного разрешения все записи = 0.
8. Выполнить только минимальную одобренную запись, один раз; сверить результат; отключить write-флаг.
9. Сообщить пользователю **фактический** статус: PREPARED / BLOCKED / SUBMITTED / SUCCESS_VERIFIED / ERROR; не объявлять успех по факту deploy.

## 10. Дополнительные действующие правила из Google Sheets 220 Master → 220_RULES

**Авторитетный исходный реестр:** [220 Master / вкладка 220_RULES](https://docs.google.com/spreadsheets/d/1xBVjjcLYqiQvy2nLtl-tGt8w_7FWefWxFa2Ltthq-7I/edit). Перед генерацией/импортом перечитывать этот реестр и проверять актуальные редакции. Ниже — консолидация по состоянию на 2026-10-06.

- **Минимальная цена для публикации на 220.lv — €10.** Shopify/current source price < €10 → исключение из публикации и offer creation; цены в Shopify или PHH не менять без разрешения.
- **Заголовки:** порядок определяется правилами категории. Без CAPS LOCK и без запятых. Для категории 4205 (палки): тип товара → бренд → модель/название → цвет, а тип товара выбирается из одобренных значений.
- **HTML-описание:** первая строка `<h2>` должна быть **точно тем же текстом**, что и заголовок соответствующего языка; после `</h2>` пустой абзац `<p><br></p>`, затем текст описания. Готовить чистый HTML, не вставлять форматированный текст из Word/Excel и изображения через copy/paste.
- **Пять языков:** LT канонический текст, переводы LV/EE/RU/FI. Supplier code/SKU в каждом языке один и тот же без перевода и изменений; в PHH UI сохранять каждую вкладку языка отдельно.
- **Производитель:** после описания логотип и краткое описание производителя, перевод по официальному сайту, с сохранением URL источника и логотипа в Master. Не выдумывать эти материалы.
- **Изображения:** минимум две; качественные, минимум 600×600, без водяных знаков и посторонних логотипов, белый фон согласно PHH. Первое — основной крупный план, второе — нижняя/обратная сторона, где применимо. Остальные могут показывать детали/упаковку.
- **Гарантия:** значение 0 использовать для наследования гарантии категории, если это предусмотрено PHH; не подставлять выдуманную продолжительность.
- **Значения характеристик:** предпочитать подтверждённые существующие словарные значения PHH, а не новые неподтверждённые произвольные значения.
- **Правила для категории 4205:** в описании должны быть материал палки, материал рукоятки, система фиксации/складывания, длина, регулируемость, количество в комплекте. Без подтверждения этих характеристик → NEEDS_DATA. Не путать максимальную регулируемую длину с вариантом-размером товара; если отдельных размеров нет, modification title оставлять пустым.
- **Готовность:** заполнены локализации, обязательные проверенные характеристики, изображения, упаковка и остальные факты → подтверждение описания/менеджером → Auto/Quality checks → предложение (offer). Без прохождения проверки не считать карточку готовой.

## 11. Особенность 220 Master: snapshot ≠ live

- Вкладка `MASTER` — **не гарантия актуальности** Shopify остатков или текущего наличия PHH. Не записывать в PHH сток из устаревшего столбца `shopify_stock_live`.
- Для LOWA RENEGADE II GTX MID TF MF Black, SKU `310921 999940` — `310921 999946`, в снимке 220 Master (строки 1425–1434 на 2026-10-06) стоит `NOT_IN_220` и `SHOPIFY_ONLY`, но это **не заменяет** живую сверку PHH.
- В тех же строках EAN/UPC в основном пустые, местами заполнены невалидными восьмизначными значениями; **не преобразовывать** их в EAN-13 и не импортировать без достоверного штрихкода. Проверить исходный barcode каждого размера.
